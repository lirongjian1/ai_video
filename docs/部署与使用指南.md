# AI Video Workflow — Supabase 版部署与使用指南

> 本版本已**彻底移除 Python/FastAPI 后端与 FFmpeg 依赖**。
> 架构：Vue3 前端（可托管 Cloudflare Pages） + Supabase（Postgres + Storage + Auth + Edge Functions）
> 视频拼接：浏览器端 MediaBunny 完成，无需任何服务端二进制。

---

## 一、准备 Supabase 项目

1. 打开 https://supabase.com 注册并 **New project**，记下项目区域和数据库密码。
2. 进入项目后，在 **Project Settings → API** 页面记下三个值：
   - `Project URL`（形如 `https://xxxxx.supabase.co`）
   - `anon public` key
   - `service_role` key（**切勿泄露到前端**）

## 二、初始化数据库

### 方式 A：SQL Editor 手动执行（推荐，最省事）

1. 打开 **SQL Editor**，新建查询。
2. 把 `supabase/migrations/20260930000001_init.sql` 全文粘贴进去执行。
   它会创建 10 张表、索引、`updated_at` 触发器、RLS 策略，以及 `media` 存储桶。
3. 再执行 `supabase/migrations/20260930000003_api_secrets.sql`
   （密钥管理表与加解密函数，见第四节）。
4. 再执行 `supabase/migrations/20260930000004_app_config.sql`
   （系统配置表，替换被托管平台禁止的数据库参数设置）。
5. 再执行 `supabase/migrations/20260930000005_user_scoped_permissions.sql`
   （统一权限模型：所有资源按用户隔离，管理员仅多一个「用户管理」权限）。
6. 最后执行 `supabase/migrations/20260930000002_cron.sql`
   （定时轮询视频任务，见第五节；执行前需先填好配置，见该节说明）。

### 方式 B：Supabase CLI

```bash
npm install -g supabase
supabase login
supabase link --project-ref <你的-project-ref>
supabase db push
```

> 执行完检查 **Database → Tables**，应能看到 profiles / projects / files / prompts /
> model_configs / characters / scenes / scripts / storyboards / tasks。
> 检查 **Storage**，应能看到 `media` 桶（public）。

## 三、创建管理员账号

本版本不再有内置 `admin/admin123`，需手动创建：

1. 打开 **Authentication → Users → Add user → Create new user**。
2. 填写邮箱和密码，勾选 **Auto Confirm User**（否则需邮箱验证）。
3. 创建完成后，回到 **SQL Editor** 执行（把邮箱换成你刚填的）：

```sql
update public.profiles
set role = 'ADMIN', nickname = '管理员'
where id = (select id from auth.users where email = 'you@example.com');
```

> 之后在系统内「用户管理」中可继续添加其他用户，只有 `role='ADMIN'` 能进用户管理页。

## 三点五、权限模型（重要）

本系统的权限规则非常简单，只有两种角色：

| 角色 | 能做什么 |
| --- | --- |
| **普通用户** | 项目管理、文件、提示词、图片、角色、场景、剧本、视频、视频合成、**模型管理**、**密钥管理** —— 全部只操作**自己创建**的数据 |
| **管理员** | 上面全部 + **用户管理**（增删改用户、分配角色与状态） |

**所有资源一律按 `created_by` 隔离，不存在共享。** 包括：

- 项目 / 文件 / 提示词 / 角色 / 场景 / 剧本 / 分镜 / 任务
- 模型配置（`model_configs`）—— 别人建的模型在你列表里看不到，也选不到
- API 密钥（`api_secrets`）—— 同一引用名（如 `OPENAI_API_KEY`）每个用户可以各存一份，
  互相看不到、也取不到对方的密钥

> 换句话说：B 用户永远无法使用 A 用户配置的模型与 Key，即使 A 是管理员。
> 管理员身份**只**影响能否进入「用户管理」页，不带来任何数据可见性。

## 四、部署 Edge Functions（后端逻辑）

### 先理解：这一步在做什么

Edge Functions 就是这个项目**原来的 Python 后端**。它负责调用各家 AI 模型的接口
（生成文本、图片、视频），以及用户管理。共 7 个：

| 函数名 | 作用 |
|---|---|
| `ai-text` | 生成提示词、生成六段分镜 |
| `ai-script` | 生成剧本分镜（`ai-text` 的入口封装） |
| `ai-image` | 调用图片模型，产物存 Storage |
| `ai-video-submit` | 提交视频生成任务给厂商 |
| `ai-video-poll` | 定时查询视频任务状态（由第 5 节的定时器驱动） |
| `model-test` | 模型连接测试 |
| `admin-users` | 用户增删改（仅管理员） |

这些代码已经写好了，在 `D:/ai_video/supabase/functions/` 目录下。
**你只需要把它们上传到 Supabase**，然后配置模型密钥。

### 路线选择

- **路线 A：网页版（推荐，不用装任何工具）** ← 不熟命令行的走这条
- **路线 B：命令行版** —— 适合以后要频繁改代码的人

### 路线 A：在 Supabase 网页后台部署

#### A-1. 创建并部署函数

1. 打开你的 Supabase 项目，左侧菜单点 **Edge Functions**。
2. 点右上角 **Deploy a new function** → 选 **Via Editor**（通过编辑器）。
3. 函数名填 `ai-text`，点创建。
4. 打开本地文件 `D:/ai_video/supabase/functions/ai-text/index.ts`，
   把**全部内容**复制，粘贴覆盖到网页编辑器里，点 **Deploy**。
5. 重复 2~4 步，依次创建这 7 个：`ai-text`、`ai-script`、`ai-image`、
   `ai-video-submit`、`ai-video-poll`、`model-test`、`admin-users`。

> **公共代码怎么处理**：`_shared/` 目录下的三个文件（`supabase.ts`、`gateway.ts`、
> `prompts.ts`）是各函数共用的。网页版不支持相对路径引入，需要为每个函数
> **单独建一份**：在函数编辑器里新建同名文件，粘贴对应内容即可。
>
> 具体哪些函数用到哪些公共文件：
> - 全部 7 个都用 `_shared/supabase.ts`
> - `ai-text`、`ai-script`、`ai-image`、`ai-video-submit`、`ai-video-poll`、`model-test`
>   都要 `_shared/gateway.ts`
> - 只有 `ai-text`、`ai-image`、`ai-video-submit` 用到 `_shared/prompts.ts`
>
> 在网页编辑器里，把 `import ... from '../_shared/xxx.ts'` 改成 `from './xxx.ts'`
> （因为平级了）。**如果你觉得这些太绕，直接用路线 B 更省事。**

#### A-2. 关闭 ai-video-poll 的 JWT 校验

1. 进入 `ai-video-poll` 函数详情页。
2. 找到 **Settings / 详情** 里的 **Enforce JWT Verification** 开关。
3. **关掉它**（因为它是被数据库定时器调用的，没有用户登录态，
   它靠自定义的 `CRON_SECRET` 密钥做鉴权）。

> 其余 6 个函数**保持开启** JWT 校验，不要动。

#### A-3. 配置模型密钥（两种方式，任选）

**方式一：系统内「密钥管理」页面（推荐，不用碰后台）**

模型密钥默认存在 Supabase 数据库表里，加密后保存，直接在登录后的系统页面里维护：

1. 用管理员账号登录系统。
2. 左侧菜单进入 **密钥管理**。
3. 点 **新增密钥**，填写：
   - **名称**：随便起，比如「OpenAI 主账号」
   - **引用名**：英文大写加下划线，比如 `OPENAI_API_KEY`
     （模型配置靠它找到密钥，只能字母/数字/下划线）
   - **密钥内容**：粘贴厂商给的 API Key
4. 保存。列表里只会显示掩码（如 `sk-1****abcd`），**明文不再回传浏览器**。
5. 之后到 **模型管理** 新增配置时，「密钥」一栏直接**下拉选择**刚才的引用名即可。

需要新增哪几个引用名，对着下面这张表填（**只配你实际会用到的**）：

| 引用名建议 | 用途 |
|---|---|
| `OPENAI_API_KEY` | OpenAI 兼容接口（文本 / 图片模型） |
| `AUTODL_API_KEY` | AutoDL ComfyUI 工作流 |
| `MINIMAX_API_KEY` | MiniMax 海螺视频 |
| `ARK_API_KEY` | 火山引擎方舟（豆包） |

> **加密主密钥**：数据库用了 `pgcrypto` 对称加密。生产环境建议在 SQL Editor 里
> 执行下面这句，把默认的开发密钥换成你自己的随机串：
>
> ```sql
> insert into public.app_config (key, value) values ('secret_key', '换成一段很长的随机字符串')
> on conflict (key) do update set value = excluded.value, updated_at = now();
> ```
>
> ⚠️ 换成新主密钥后，**之前用旧密钥保存的密钥记录将无法解密**，需回页面重新填一遍。
> 建议一开始就设置好。不改也能跑，但安全性依赖数据库本身的访问控制。

**方式二：Edge Function Secrets（环境变量）**

如果你更习惯用环境变量，也可以走后台配置，效果等价：

1. **Project Settings**（齿轮图标）→ **Edge Functions** → **Secrets**。
2. 逐个 **Add new secret**，Name 填引用名（如 `OPENAI_API_KEY`），Value 填密钥。
3. 另外还要加一个 `CRON_SECRET`（自己编一个长随机串，第五节要用）。

> Edge Function 取密钥的顺序是：**先查数据库表，查不到再读环境变量**。
> 所以两种方式可以混用，数据库里配过的优先。

> `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_ANON_KEY`
> 由平台自动注入，**不用手动加**。

#### A-4. 之后在「模型管理」页选择密钥

系统里添加模型时，**「密钥」一栏从下拉列表里选择**（列表来自「密钥管理」页）。
不再需要手工输入引用名，避免拼错大小写。

### 路线 B：用命令行部署（一次性搞定，推荐给会用终端的）

#### B-1. 安装并登录 CLI

```bash
npm install -g supabase
```

安装完成后登录（会自动打开浏览器让你点授权）：

```bash

```

#### B-2. 关联到你的项目

先获取 **project-ref**：在 Supabase 网页项目的 URL 里，形如
`https://supabase.com/dashboard/project/abcdefghijklmn`
斜杠最后那串 `abcdefghijklmn` 就是 project-ref。

```bash
cd D:/ai_video
supabase link --project-ref abcdefghijklmn
```

> 执行后可能提示需要数据库密码，就是第 1 步建项目时设的那个。

#### B-3. 配置密钥

**推荐做法**：模型密钥不用在这里配，登录系统后在 **密钥管理** 页面添加即可
（见 A-3 方式一）。环境变量只需要配定时轮询的保护密钥：

```bash
# 定时轮询保护密钥（自定义一个长随机串，务必与第 5 节一致）
supabase secrets set CRON_SECRET=your-random-cron-secret
```

如果你更想用环境变量管模型密钥，也可以照常设置（与数据库里的密钥可共存，
数据库优先）：

```bash
# OpenAI 兼容类（文本 / 图片）
supabase secrets set OPENAI_API_KEY=sk-xxxxxxxx

# AutoDL ComfyUI
supabase secrets set AUTODL_API_KEY=your-autodl-token

# MiniMax 海螺
supabase secrets set MINIMAX_API_KEY=your-minimax-key

# 火山引擎 Ark（豆包）
supabase secrets set ARK_API_KEY=your-ark-key
```

#### B-4. 部署全部函数

逐条执行（`_shared` 公共目录会被自动打包，无需单独部署）：

```bash
supabase functions deploy ai-text
supabase functions deploy ai-script
supabase functions deploy ai-image
supabase functions deploy ai-video-submit
supabase functions deploy ai-video-poll --no-verify-jwt
supabase functions deploy model-test
supabase functions deploy admin-users
```

> **为什么只有 `ai-video-poll` 加 `--no-verify-jwt`**：
> 其余函数都是用户在浏览器里带着登录态调用的，Supabase 会自动校验 JWT。
> 而 `ai-video-poll` 是第 5 节的数据库定时器调用的，**没有用户登录态**，
> 所以必须关掉 JWT 校验；它靠请求头里的 `CRON_SECRET` 做身份验证。

#### B-5. 验证部署成功

打开 Supabase 网页 → **Edge Functions**，应该能看到 7 个函数，状态正常。
点进任意一个看 **Logs**，调用时会有记录。

### 常见问题

**Q：`supabase login` 卡住 / 打不开浏览器？**
换路线 A（网页版），效果完全一样。

**Q：部署报错 `SUPABASE_ACCESS_TOKEN` 未设置？**
先完整执行 `supabase login`，或改用网页版。

**Q：网页版下 `_shared` 引用报错？**
网页编辑器不支持 `../` 相对路径。要么按 A-1 的说明在函数内建平级文件并改 import
路径，要么直接用路线 B。

**Q：模型测试提示「密钥无效」？**
先在 **密钥管理** 页确认该密钥状态为「启用」，且值没填错。
若用环境变量方式，则检查「模型管理」页选的引用名与 Secrets 的 Name 是否逐字符一致（区分大小写）。

## 五、配置视频任务定时轮询

视频生成是异步的（厂商要跑几十秒到几分钟）。为避免撞 Edge Function 执行时限，
拆成「提交」+「轮询」两段，轮询由数据库定时任务驱动。

**第一步：填入项目地址与轮询密钥**

在 **SQL Editor** 里执行（把两个占位值换成你自己的）：

```sql
-- 把 https://xxxxx.supabase.co 换成第 1 步拿到的 Project URL
-- 把 your-random-cron-secret 换成第 4 节设置的那串随机密钥（必须完全一致）
insert into public.app_config (key, value) values
  ('supabase_url', 'https://xxxxx.supabase.co'),
  ('cron_secret',  'your-random-cron-secret')
on conflict (key) do update set value = excluded.value, updated_at = now();
```

> ⚠️ **不要用 `alter database postgres set app.settings.xxx`**（早期文档写过这句）。
> Supabase 托管实例不开放这个权限，会报
> `42501: permission denied to set parameter`。
> 本项目的配置统一存在 `app_config` 表里，用上面这句 insert 即可。

**第二步：创建定时任务**

先启用扩展：

```sql
create extension if not exists pg_cron with schema extensions;
create extension if not exists pg_net with schema extensions;
```

然后把 `supabase/migrations/20260930000002_cron.sql` 里的
`select cron.schedule(...)` 那段**整体复制**到 SQL Editor 执行。
它会每 15 秒调用一次 `ai-video-poll`，把已提交的视频任务推进到完成。

> 该文件已改为从 `app_config` 表读取配置，不再依赖数据库参数。

验证是否建成功：

```sql
select jobname, schedule, active from cron.job;
```

正常应看到一行 `poll-video-tasks`，`active` 为 `true`。

> **前提**：`pg_cron` 扩展需要 Supabase 付费套餐（Pro 及以上）。
> 免费版用不了的话，改用外部定时服务（如 UptimeRobot、cron-job.org）
> 每 15 秒 GET 一次
> `https://xxxxx.supabase.co/functions/v1/ai-video-poll`，
> 并在请求头加上 `x-cron-secret: 你的CRON_SECRET`。

## 六、配置并启动前端

前端配置**不用环境变量**，直接写在一个代码文件里，改一次就永久生效。

**第一步：填写配置文件**

打开 `D:/ai_video/frontend/src/lib/config.ts`，填入两个值：

```ts
// 在 Supabase 后台 → Project Settings → API 页面复制这两项
export const SUPABASE_URL = 'https://xxxxx.supabase.co'
export const SUPABASE_ANON_KEY = '粘贴 anon public 那把长密钥'
```

> - `SUPABASE_URL` = 页面里的 **Project URL**
> - `SUPABASE_ANON_KEY` = 页面里的 **anon public**
> - **别填成 `service_role`**，那把是管理员密钥，绝不能进前端

**第二步：装依赖并启动**

```bash
cd D:/ai_video/frontend
npm install
npm run dev
```

访问 http://127.0.0.1:5173 ，用第三节创建的邮箱密码登录。

> 生产构建：`npm run build`，产物在 `frontend/dist`。
> 因为配置写在源码里，**每次改配置都要重新构建**才算生效。

**为什么 anon key 可以写在代码里？**

`anon public` 是 Supabase 专门设计给前端的公开密钥，它本身不含任何特权，
数据安全由**数据库的 RLS 策略**保证（本项目已配好：普通用户只能读写自己的行）。
真正不能泄露的是 `service_role` key，它绕过所有 RLS，只存在于 Supabase 后台。

## 八、使用流程

1. **密钥管理**：录入各厂商 API Key（加密入库，页面只显示掩码）。
   密钥按用户隔离——每个用户维护自己的一套，互不可见。
2. **模型管理**：分别配置文本 / 图片 / 视频模型，填接口地址、模型名，
   「密钥」一栏下拉选择上一步的引用名，点击「测试连接」验证。
   模型配置同样按用户隔离，只能看到和使用自己的配置。
3. **提示词管理**：输入关键内容，由文本模型生成角色三视图或场景提示词。
4. **图片管理**：选择提示词和图片模型生成参考图；也可直接上传。
5. **剧本管理**：输入故事描述，生成固定 6 段 × 10 秒的分镜。
6. **分镜 → 视频**：在剧本分镜下选择视频模型加入生成队列。
   提交后在「工作台 / 任务管理」查看进度（由定时轮询推进）。
7. **视频合成**：在「视频合成」页选 ≥2 个视频、排序、点开始。
   拼接在**浏览器本地**完成，完成后自动进入视频资产库。

## 九、与旧版（Python 后端）的差异

| 项目 | 旧版 | 新版 |
|---|---|---|
| 后端 | FastAPI + uvicorn | 无（Supabase 托管） |
| 数据库 | MySQL 8 | Supabase Postgres |
| 文件存储 | 本地 `storage/` 目录 | Supabase Storage（`media` 桶） |
| 登录 | 自研 JWT + BCrypt，用户名 | Supabase Auth，**邮箱** + 密码 |
| 默认账号 | admin / admin123 | 需后台手动创建 |
| 权限模型 | 单管理员制，数据共享 | 多用户，**所有资源按用户隔离**；管理员仅多一个「用户管理」权限 |
| 模型 Key | 加密存 MySQL | 加密存 Postgres（页面可管理，**按用户隔离**），或 Edge Function Secrets |
| 视频拼接 | 服务端 FFmpeg | 浏览器端 MediaBunny |
| 任务执行 | BackgroundTasks 内存队列 | Edge Function + pg_cron 轮询 |

### 注意事项

- **登录方式变了**：现在用**邮箱**登录，不是用户名。
- **视频拼接限制**：MediaBunny 采用直通封装，要求所有片段**编码格式一致**
  （同一模型产出的视频通常一致）。不一致时会明确报错，需先统一转码。
  拼接在浏览器端进行，会占用本机 CPU，且需浏览器支持 WebCodecs（Chrome/Edge 均可）。
- **存储配额**：Supabase 免费版 Storage 1GB，视频文件较大时注意容量。
- **旧 `backend/` 目录**：已废弃，仅作逻辑参考，可安全删除，不影响部署。

## 十、常见问题

**Q：上传/预览视频报 CORS 或 403？**
检查 `media` 桶是否为 public，以及 RLS 策略是否执行成功（第二节的 SQL 末尾部分）。

**Q：视频任务一直停在「执行中」？**
检查第五节定时任务是否已创建、`app_config` 表里的 `cron_secret` 是否与
Edge Function 的 `CRON_SECRET` 一致。
可手动执行 `select * from cron.job_run_details order by start_time desc limit 5;` 排查。

**Q：模型连接测试失败？**
先看 **密钥管理** 页里该密钥是否「启用」、内容是否正确。
若用环境变量方式，则确认引用名与该 Secret 名称**完全一致**（区分大小写）。
数据库里的密钥优先于环境变量。

**Q：执行 SQL 报 `42501: permission denied to set parameter "app.settings.xxx"`？**
Supabase 托管实例不允许改数据库自定义参数。本项目已改用 `app_config` 配置表，
请执行 `20260930000004_app_config.sql`，然后用 `insert into public.app_config ...`
写入配置（见第五节），不要再执行 `alter database ... set app.settings.*`。

**Q：视频合成提示编码不一致？**
把片段统一转码为相同编码（如都是 H.264 + AAC）后再拼接。

**Q：想换回自建后端？**
`backend/` 目录完整保留，按原 README 启动即可，两者互不干扰。
